# Polymorphic Favorite Drink Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a polymorphic `favorite_drink` association to `CoffeePlace`, backed by an STI `Beverage` base class with `Coffee` and `Tea` subclasses, with seed data and a form control to pick one.

**Architecture:** One new STI-backed table (`beverages`, discriminated by `type`) holds `Coffee` and `Tea` rows. `CoffeePlace` gets a nullable polymorphic `belongs_to :favorite_drink`. The `favorite_drink_type` column stores the STI subclass name (`"Coffee"`/`"Tea"`), which is exactly what Rails' polymorphic association machinery already does with STI targets — no custom type-column handling needed.

**Tech Stack:** Rails 8.1, RSpec + rspec-rails, Capybara (feature specs), SQLite.

## Global Constraints

- Follow the existing spec style: plain `Model.new`/`Model.create!` in specs, no FactoryBot (not in the Gemfile).
- Migrations target `ActiveRecord::Migration[8.1]`, matching the existing migration.
- `db/schema.rb` is regenerated by running the migration — do not hand-edit it.
- Test DB schema syncs automatically via `ActiveRecord::Migration.maintain_test_schema!` in `spec/rails_helper.rb` — no separate `db:test:prepare` step needed once `bin/rails db:migrate` has run against dev.
- `favorite_drink` is optional on `CoffeePlace` (existing places have none).

### Task 5: Form UI — select a favorite drink, show it on the index

**Files:**
- Modify: `app/controllers/coffee_places_controller.rb`
- Modify: `app/views/coffee_places/new.html.erb`
- Modify: `app/views/coffee_places/index.html.erb`

**Interfaces:**
- Consumes: `CoffeePlace#favorite_drink` (Task 3), seeded `Coffee`/`Tea` rows (Task 4).
- Produces: no new interfaces — this is the leaf UI task.

A plain HTML `<select>` can only submit one value per field, but a polymorphic association needs two (`favorite_drink_id` and `favorite_drink_type`). Rather than a second hidden field kept in sync with JS, encode both into one option value as `"Type-id"` (e.g. `"Coffee-3"`) and split it back apart in the controller.

- [ ] **Step 1: Add the encoded-value select to the new-place form**

```erb
<%# app/views/coffee_places/new.html.erb — insert after the rating field, before the submit button %>
    <% selected = @coffee_place.favorite_drink ? "#{@coffee_place.favorite_drink_type}-#{@coffee_place.favorite_drink_id}" : "" %>
    <%= form.label :favorite_drink, "Favorite drink" %>
    <%= form.select :favorite_drink,
          grouped_options_for_select(
            {
              "Coffee" => Coffee.order(:name).pluck(:name, :id).map { |name, id| [name, "Coffee-#{id}"] },
              "Tea" => Tea.order(:name).pluck(:name, :id).map { |name, id| [name, "Tea-#{id}"] }
            },
            selected
          ),
          include_blank: true %>
```

- [ ] **Step 2: Parse the encoded value in the controller**

```ruby
# app/controllers/coffee_places_controller.rb
class CoffeePlacesController < ApplicationController
  def index
    @coffee_places = CoffeePlace.all.order(created_at: :desc)
  end

  def new
    @coffee_place = CoffeePlace.new
  end

  def create
    @coffee_place = CoffeePlace.new(coffee_place_params)
    assign_favorite_drink

    if @coffee_place.save
      redirect_to coffee_places_path, notice: "Coffee place added."
    else
      render :new, status: :unprocessable_content
    end
  end

  private

  def coffee_place_params
    params.expect(coffee_place: [ :name, :address, :rating, :favorite_drink ])
  end

  # The form posts favorite_drink as "Coffee-3"/"Tea-1"/"" (see new.html.erb) rather than
  # separate id/type fields, since a plain <select> can't submit two params from one choice
  # without JS. Split it back into the polymorphic id/type pair here.
  def assign_favorite_drink
    encoded = coffee_place_params[:favorite_drink]
    return if encoded.blank?

    type, id = encoded.split("-", 2)
    @coffee_place.favorite_drink_type = type
    @coffee_place.favorite_drink_id = id
  end
end
```
